# Workforce `core` boundary

The `eutheto-workforce` workspace crate owns the official Workforce domain implementation. WF-001 provides pack-owned UUIDv7 identities, the typed four-map model for current and reserved MVP semantics, generated record/command schemas and editor/AI metadata, bounded document decoding and structural/reference validation, explicit score-policy shape checks, pure typed CRUD commands with exact inverses, current portable-v1 conversion, and bounded people CSV detection, preview and review rebuilding. WF-002 adds timezone-aware recurrence, calendar/reporting windows, deterministic regeneration review and atomic occurrence ownership commands. WF-003 adds bounded assignment analysis, mathematical compilation and independent original-domain evaluation contributions; WF-004 extends them with scoped elapsed minimum rest. WF-006 adds complete supported-subset Planning IR compilation and strict Workforce candidate projection. WF-007 adds independent scope, verification, initial score, bounded evidence/share hooks and the real `WorkforcePack` adapter. It remains **unregistered**: application/CLI dispatch, durable CSV apply and Phase05 closure are separate gates.

## Boundary

It may use the domain API, stable value types, solver-neutral planning IR, and normalized verification contracts. It must not depend on Tauri, Vue, SQLite, credential stores, network providers, OR-Tools, Pumpkin, or backend-native objects.

`WorkforcePack` implements the current domain contract without registering itself. A temporary registry can exercise its descriptor/catalog and real hooks; production registration and application integration remain dependency-ordered work. No partial `DomainPack` implementation or synthetic solver authority is permitted.

`validation::decode_document` bounds raw input before typed decoding; `validate_document` also handles an existing host document without changing it. Structural checks include normalized owned-identity uniqueness, expected reference kinds, explicit scope safety, exact external-ID uniqueness, temporal coherence, coverage count ordering, and workload peer/target agreement. Valid-but-contradictory coverage remains editable. Missing score policy is an incomplete draft, not a decoding error. Known later semantics are retained data, not executable capability.

Document limits reuse the shared contract bounds: 16 MiB serialized bytes, depth 32, 16 KiB strings and 100,000 aggregate items/nodes. Each host map and reference list is capped at 10,000 entries; occurrence ledgers are capped at 4,096 per template and 32,768 per document. Policy limits are 15 explicit score levels plus the reserved final rank level, 256 workload definitions and 32 piecewise segments. Cross-field and whole-document bounds can make a particular combination smaller than these individual ceilings.

`commands::apply_batch` applies at most 1,000 typed operations on a private working copy. Every prefix must remain structurally valid; deletes never silently cascade references. Updates retain kind, untouched records retain exact JSON, and reversed ordinary command inverses restore original field presence and spelling. Both forward and inverse batches must fit the shared 16 MiB serialized command bound. Returned changes carry record paths and exact before/after values; persistence, revisions and production routing remain host-owned.

`portable::export_portable` and `import_portable` preserve the four raw record maps and declared `nonsemantic.*` extensions under Workforce portable version 1, requiring exactly `official.workforce.portable` at version 1. Import replaces only the explicit host shell's domain and extensions; host identity, metadata, settings and versions remain unchanged and are validated with the resulting document. Unknown semantic requirements, record variants and older/newer Workforce versions fail without a fabricated migration. Depth/safety checks precede recursive serialization or cloning of caller-built payloads. Global portable version 2, internal snapshots and their genuine historical migrations remain host-owned.

## Temporal generation and review

`temporal::resolve_shifts` resolves existing identities without minting new ones. Generated recurrence uses inclusive scenario-zone start dates, weekdays, exclusions and half-open effective dates; its actual local start date must remain in the horizon after resolution. Final-date overnight ends are not clipped. Manual/detached shifts instead use explicit start-instant membership and preserve their exact intervals and fold choices. Detached origins suppress their original occurrences even when edited outside the horizon.

`preview_generation` compares validated before/prospective documents, retaining unresolved known prior timing without inventing instants. It reuses recorded identities, rejects conflicting ownership across both active and dormant ledger/detached entries, and derives only unseen identities under the frozen `occurrence-id-v1` byte contract. It returns compact timing/diff data and at most one ordinary add-occurrence command, bound to the exact prospective document hash. The host must enforce that binding and separately compose reviewed edits under its revision/transaction boundary; this Rust value is not approval custody.

Atomic `add_occurrence_identities`/`remove_occurrence_identities` commands target bounded sets of templates without copying whole templates into changes. `detach_shift`/`reattach_shift` transfer an existing identity between ledger and stored instance, retaining exact raw UUID key/value spelling and ordinary inverses. Dormant transfers are allowed: detaching may activate an edited one-off and reattaching may deactivate it under current recurrence. Callers must review the resulting activity diff.

`resolve_calendar` returns whole windows intersecting an explicit instant query; `reporting_window` finds a unique civil reporting-date owner independently of clock boundaries. Custom periods must remain ordered/nonoverlapping after DST resolution, and ambiguous reporting-date ownership fails rather than double-counting. Explicit gap/fold policies apply throughout. Intervals expose exact signed scheduled and elapsed durations, not rounded minute substitutes.

Temporal vectors are bounded to 42,768 shifts per side, 85,536 diff entries and 32,768 calendar windows; compound identity commands retain the existing per-template/document limits and at most 10,000 template targets. Command changes additionally stop before 85,536 entries or 64 MiB serialized bytes. Cross-field document bounds can lower these ceilings. See the [WF-002 contract](../../../docs/roadmap/05-workforce-core-vertical-slice.md#wf-002-temporal-module-contract) for identity encoding, ownership precedence and complete temporal semantics.

## Assignment-rule contributions

`assignment_rules::analyze_assignments` builds the bounded person/shift candidate graph, retains every source-owned rejection, reports obvious coverage and hard-lock contradictions, and estimates this contribution before IR variable allocation. `compile_assignment_rules` returns pair-associated Boolean variables, hard constraints and reachable provenance—not a complete `PlanningProblem`, objective, projection or registered pack.

Active Eligibility, Availability, Coverage, NoOverlap and MinimumRest rules use conjunctive person/team/type/category/reporting-weekday/location scopes. Person activity covers the whole shift independently of authored rules. Eligibility requires allowed assignment type and whole-shift qualifications; adjacent grants of the same qualification may join, but even a nanosecond gap fails. Different partial qualifications cannot alternate to satisfy one whole-shift `any` member.

Ordinary Unavailable and AvailableOnly records require a matching active Availability rule. Approved time off is an unconditional fact; requested time off is not hard. Record type/location restrictions still apply. Instant and recurring weekly windows clip to their effective range. AvailableOnly records are conjunctive, while windows within one record union; an empty effective intersection is vacuous. DST policy and the full overnight tail remain explicit.

Coverage counts a selected person once for total headcount and independently for each matching qualification minimum. Embedded and active standalone requirements remain separate conjunctive owners; equivalent canonical minima deduplicate only within one owner. Preferred counts have no hard effect. NoOverlap uses strict half-open intersection; touching endpoints do not overlap. Symmetric category compatibility exempts only its owning rule. Compatibility does not choose workload accounting: a workload bucket's explicit `sum` versus `union` policy remains separate, and this contribution computes no workload hours.

NoOverlap rules with no category waivers compile maximal interval cliques as `AtMostOne`, scoped independently per person and rule. End events precede starts at the same instant, preserving touching-endpoint behavior. Rules with any category waivers retain pairwise conflicts: removing compatibility edges need not leave an interval graph. This uses existing Boolean primitives, not native interval variables or a new backend capability.

MinimumRest concerns every matching chronological pair for the same person: common `scope` matches both shifts, `afterScope` matches the source, and `beforeScope` matches the target. The target must start at or after the source start; equal-start distinct shifts may match both directions independently of UUID order. Exact signed elapsed target-start minus source-end must meet `minimumMinutes`. Equality passes; one nanosecond short fails. Overlap fails even a zero-minute rule, regardless of NoOverlap compatibility. Intervening assignments do not reset rest, and full overnight/DST intervals remain intact. Violating pairs add `AtMostOne` constraints; they do not prune otherwise admissible candidates.

For example, a 600-minute call-to-clinic rule has `afterScope.categories: ["call"]`, `beforeScope.categories: ["clinic"]` and `people: {"kind":"all"}` in all three scopes. A call ending at 10:00 UTC permits a clinic starting at 20:00 UTC, but not 19:59:59.999999999 UTC. Reverse clinic-to-call rest requires a separate directional rule. This is an explicit scheduling policy, not a certified legal or regulatory compliance preset. Review the applicable jurisdiction, date and local requirements. Typed rule add/update commands and portable documents preserve this policy now; Workforce CLI application examples remain gated on WF-007 registration and WF-008 dispatch.

For downstream workload accounting, `sum` adds each assignment's chosen measurement; `union` counts elapsed time in the union of that person's assigned intervals for the bucket, so simultaneous compatible work counts once. Structural validation permits `union` only with `elapsedMinutes`, not scheduled-wall-clock minutes or assignment counts. Computing these totals remains outside WF-003.

`evaluate_assignment_rules` validates identities and duplicates before scope filtering, then evaluates the original document and selected pairs without consuming compiler pruning, constraints or backend claims. Identified but inadmissible selections remain visible and fail the relevant predicates. It emits exactly one bounded summary per handled obligation, with exact checked/violation counts and at most one canonical first-failing witness.

All operations bind the exact source document with the existing serialized-document BLAKE3 recipe. Their sorted handled/remaining partition includes every active authored rule, person activity fact, approved-PTO fact and Hard lock. Other active families and Hard locks remain unhandled; a contribution is not complete verification. Hard-lock readiness diagnoses rejected/unresolved pairs, active-rule overlap, scoped minimum-rest conflicts and excessive hard headcount. Rest readiness uses original resolved Hard locks even if a member is individually inadmissible; it does not enforce locks or claim solver-proven infeasibility.

Rest summaries count all applicable ordered pairs, including a satisfied suffix without walking its Cartesian pairs. Only the canonical first violation retains directional source/target Entity facts, expected minutes, observed signed whole seconds and signed subsecond nanoseconds. Together those numeric fields preserve negative and extreme gaps without rounding or an overflowing total-nanosecond integer. Empty resolved scopes yield a satisfied summary with zero predicates; inactive rules yield no obligation.

Fixed ceilings are 1,000,000 inspected pairs, 20,000,000 work steps, 32,768 expanded availability intervals and 100,000 selected pairs. Analysis/compilation also honor caller Planning IR record/reference/byte and per-record limits; evaluator retention is bounded to 100,000 records, 1,000,000 references/items and 16 MiB. Counters are cumulative, including temporary structural indexes. Optional cancellation uses the caller's real token; `None` is still finite-work bounded. Resource or temporal failure returns an error, never truncated success or solver infeasibility.

The legal cross-layer Core harness compares exhaustive tiny selections with primitive mathematics, injects compiler defects, and freezes coverage/no-overlap/directional-rest identities. Rest cases also prove typed-command inverse and portable semantic round trips. `just workforce-rule-worker-test` additionally requires `EUTHETO_TEST_ORTOOLS_ARTIFACT` to name an approved installed artifact and exercises feasible/infeasible assignment and rest models with the real worker, without a helper fallback. This remains contribution-level evidence, not production pack acceptance or full workload benchmarking.

## Complete compiler and candidate projection

`assignment_rules::compile_workforce(document, context)` returns `WorkforceCompilation`: one canonical, validated `PlanningProblem`, the exact `source_document_hash`, source-owned `rejections`, and the existing `validation` report. The contribution APIs above retain their partial contract. Complete compilation requires an authored score policy and rejects every active unsupported Required rule, preference, Hard lock and Soft lock before constructing IR. Inactive definitions, unlocked assignments and unused workload/score-level definitions introduce no objectives. Supported but impossible requirements produce an infeasible model, not a weakened one.

The final minimized `StableAssignmentRank` uses **all source people and all resolved in-horizon shifts**, sorted by typed IDs before candidate pruning. For zero-based person/shift indices `p,s` and shift count `S`, `rank = p*S+s+1`. An inactive or otherwise noncandidate person retains rank slots without receiving variables; adding/removing that person may renumber later ranks and change tie-break outcomes. Pruning never renumbers surviving pairs. Equal rank sums may tie: this is not a unique-schedule or fairness guarantee.

One minimized level, `official.workforce.objective.assignment.rank`, contains the positive selected-pair ranks under category `official.workforce.score.assignment.rank`. Each candidate Boolean has a `[0,1]` integer linked by two enforced equalities; auxiliary integers are not domain assignments. Bounds are zero through the checked sum of candidate ranks. Zero candidates retain a zero-valued level with no terms. The independent authority recomputes the source-universe rank without reading these terms: nonzero category totals equal the rank, while a zero total has no category entry.

Metadata binds source scenario/revision, `official.workforce`, projection version 1, compiler `official.workforce.compiler` and crate version. Compiler-owned integer keys are `official.workforce.rank.version` (1), `official.workforce.candidates.inspected`, `official.workforce.candidates.after.activity`, `official.workforce.candidates.after.assignment.type`, `official.workforce.candidates.after.qualification`, `official.workforce.candidates.after.availability`, and `official.workforce.rejection.facts`. Caller collisions and malformed metadata fail; other caller semantic metadata is preserved and affects the model hash. The raw source hash stays outside semantic IR, so display-only changes preserve model identity/hash at the same scenario/revision. Rejected pairs retain their typed diagnostic provenance beside the model rather than as orphan IR records.

`project_workforce_candidate(problem, candidate, solution_id, limits)` delegates generic candidate validation/projection and then decodes **every** returned assignment without rewriting the result. Every candidate pair requires a Boolean, including explicit `false`; missing values are not unselected assignments. Unknown supplied variables and out-of-domain supplied integers fail. `decode_workforce_assignment` returns `(AssignmentPair, bool)` from assignment ID `official.workforce.assignment.<person-uuid>.<shift-uuid>`, entity kind `official.workforce.assignment`, and entity ID `<person-uuid>.<shift-uuid>`. Both references must agree and use canonical lowercase hyphenated UUIDv7 spelling. Wrong pack/version, malformed pair identities, integer/interval/absent assignment values and mismatched references fail with bounded codes. Well-formed model-relative projection does not prove the pair exists or is valid in the original scenario.

Full-model serialization, including root punctuation, enum wrappers, metadata, channels, terms and projections, is measured before output construction. Final IR, source analysis/diagnostics and generic-operation scratch share cumulative retention limits; serialized IR also has its own shape ceiling. Effective caller limits cannot exceed supported defaults. Borrowed raw string lengths are bounded before projection serialization can scan them for escapes. Generic normalization/validation are finite precharged phases, with cancellation checked before/after—not falsely advertised as interruptible internally. Projection has no cancellation-token parameter. A 100-person × 28-coincident-shift capacity probe reached the explicit 20-million-step limit; this is not evidence of large-workload support. Product workload sizing and benchmark acceptance remain WF-008 gates.

`just workforce-rule-worker-test` exercises earlier contribution cases and complete compile → approved real worker → Workforce projection → generic structural verification → independent Workforce acceptance → bounded Share Result. The complete fixture proves authoritative rank 5 and zero feasibility, preserves unselected decisions as false, rejects stale/incomplete normalized output and preserves supported infeasibility. A validly encoded weakened-coverage model produces a real worker candidate that is quarantined against the original scenario. Exhaustive source/mathematics checks and fixed source-only expected selections separately defend verifier truth. This is unregistered acceptance evidence, not production dispatch, large-workload acceptance or Phase05 closure.

## Independent authority, evidence and sharing

The public `assignment_rules` hooks are `workforce_verification_scope(document, revision, cancellation)`, `score_workforce_solution(document, solution, cancellation)` and `verify_workforce_solution(document, solution, context, score, cancellation)`. Scope independently enumerates every person activity fact, approved-leave fact and active supported Required rule; it never trusts compiler/evaluator handled lists. Each semantic binding hashes the whole original document plus binding kind/identity under a versioned separator. Display-only source changes therefore change verification bindings even when the planning model is unchanged.

Both true and false normalized decisions must have unique, canonical person/shift identities that exist with the correct kinds in the original snapshot. Required outcomes use original domain predicates; feasibility is the checked violation measure, and rank is independently reconstructed from the unpruned source universe. Verification rejects a mismatched supplied score, source document, solution or scope context. The existing generic acceptance reviewer owns model-relative structural checks, complete scope/report reconciliation and quarantine. Backend objectives are reconciliation evidence only: a mismatch never replaces authoritative scoring.

Whole nested typed inputs receive borrowed cardinality, raw-string/key, depth, aggregate-byte/item and finite-work checks before generic allocating validation, checksums, normalization or copies. Authority operations retain the existing 20-million-step ceiling and cumulative 16-MiB logical scratch/output budget; these are not RSS measurements. Domain-IR inputs also obey their one-million-item ceiling, while document/share schemas impose the stricter 100,000 aggregate-item and depth-32 bounds. Generic indivisible constructor/hash phases are precharged and checked for cancellation before/after; tokenless trait hooks remain finite-work operations, not new parent-deadline cancellation promises.

`render_workforce_evidence(document, request)` supports only:

- **Validation:** a freshly matching current code/severity summary, with the same stable code as issue ID and message key, empty submitted parameters and no submitted path/entity/rule. It does not identify a historical occurrence when another current finding has the same code.
- **Assignment:** the exact recorded Boolean decision and freshly recomputed pair-local activity, approved-leave, eligibility and availability facts. Supplied local rule outcomes, metrics, initial-rank contributions and source provenance must match recomputation; aggregate coverage/overlap/rest assertions and locked-state claims are rejected. This is not full-schedule, current-head, historical-execution or optimality proof. The host owns document/result association.

Infeasibility, Counterfactual, SolutionDifference, Repair and OptimalityStatus evidence, and counterfactual compilation, return the existing unsupported-capability error. No result view is implemented or advertised; all five later score/provenance/result/import/export UI groups stay empty. Fast validation is structural; full validation reuses bounded assignment readiness. Missing score policy and active later semantics remain explicit execution preconditions, not invented draft defaults.

`build_workforce_share_result(document, accepted, options)` freshly rechecks the complete original scope, report outcomes, metrics/warnings and score before returning anything. Public checksums alone cannot authorize a share. Share v1 contains only schema/scenario/revision/solution identities, accepted/report/document hashes, verified-feasible status, the evidence privacy flag, selected assignment/person/shift IDs and the authoritative initial score. When requested, sorted evidence references are exactly source-derived selected-decision provenance; even hidden or unselected input evidence is checked. Names, notes, external IDs, raw records/backend output and arbitrary caller facts are excluded. These identifiers are pseudonymous, not a claim of anonymization.

The caller supplies the explicit current or historical snapshot. The hook verifies matching content and internal revision bindings; it cannot infer repository head or prove that a historical backend run occurred. Every nested share object is closed, the generated schema is checked before return, and malformed, forged, stale-content or over-budget inputs return an error without a partial payload.

## People CSV review

`people_csv::detect_people_csv` reports comma, semicolon and tab candidates without choosing a delimiter or header. It retains at most two sample records per candidate, with UTF-8-safe 64-byte cell prefixes. The pinned `csv-core` parser supplies CSV quoting semantics; original bytes are independently checked for UTF-8, unsupported encodings and binary controls before quote removal can conceal them. One initial UTF-8 BOM may be stripped for parsing, but every original byte remains part of the source digest.

`preview_people_csv` consumes a caller-supplied stream, explicit column/blank policy, explicit creation defaults, reference mappings and row decisions. Header names are not identity. Only exact existing external IDs auto-match; missing, changed or similar IDs require an explicit Add, Update or Skip decision. Add uses a caller-supplied unused UUIDv7 `PersonId` and may omit an external ID. Duplicate person or external-ID targets block approval until all but one conflicting row are explicitly skipped. Text is not trimmed or case-folded. Structured cells retain raw JSON until generated field-schema and reference-kind validation; complete unchanged records retain their exact JSON spelling.

Rejected rows carry bounded logical record numbers and reason codes, not echoed source cells or parser exceptions. They never enter the proposed ordinary command batch. Unresolved/conflicting rows block the batch and review artifact. A reviewable batch is checked through the same structurally valid-prefix command path as ordinary edits; a no-change review still binds its source and rejected rows. Cancellation is checked during reads, between rows, between command prefixes and before returning approval.

`decode_people_csv_review` rejects oversized, deep, unsafe, duplicate-member, unknown-version and alternate typed JSON representations. `rebuild_review` requires an independently retained approval digest and freshly recomputes against the actual current scenario, revision and source stream. The binding includes original source bytes, scenario content, parser/limit versions, mapping, decisions, accepted commands and rejected rows. Neither API supplies approval custody, a revision lock or durable apply: those remain host-owned staged application-integration responsibilities before WF-008 closure.

Fixed CSV limits are 16 MiB original input, 10,000 data records plus an optional header, 64 columns, 16 KiB per decoded cell, 256 KiB per decoded record, 1,000 mutations, and 200 rejected rows within 64 KiB. Mapping and decisions are each capped at 1 MiB; review artifacts at 2 MiB; previews at 16 MiB; detection output at 64 KiB. Shared document, command and portable-JSON bounds also apply, so combinations may reach an aggregate limit before an individual ceiling.

## Generated contracts

`schemas/domain-packs/workforce.contract.json` is the source-v3 authoring contract. `just generate` expands its bounded local definitions into the existing runtime schema vocabulary, emits the Rust command identities consumed by dispatch, and produces the internal/portable schema artifacts, command contracts, TypeScript payload types, editor manifest and explicit AI-tool subset. Source version 3 does not change the Workforce internal or portable version 1.

Both document ingress paths and command dispatch reject raw JSON representations outside those schemas before accepting records. Each operation owns its parsed, validated schemas and reuses them across batch prefixes; no global schema cache is used. Accepted records are not normalized, so inverse replay retains their exact spelling.

The portable artifact is checked against actual pure conversion, not application import/export authority. Share Result v1 is generated from the same authoritative contract and checked against freshly verified accepted results. The schema vocabulary supplies closed shapes, UUID format and exact identifier/hash lengths; runtime source identity, canonical UUIDv7/hash and cross-field checks provide the stronger semantic guarantees. Score/provenance/result/transfer UI metadata remains empty. Editor and AI metadata describes current typed data/proposal shapes, not an implemented desktop or assistant flow.
